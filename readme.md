# Frontend AI Chatbot

Односторінковий застосунок на React + Vite для взаємодії з Puter AI через браузерний SDK.

## Передумови

- Node.js 20 LTS (перевірити `node -v`)
- npm 10+ (перевірити `npm -v`)
- Доступ до Puter (акаунт або API-токен)
- Браузер з підтримкою ES2023 (Chrome 119+, Edge 119+, Firefox 121+)

## Установка

1. Клонувати репозиторій:
   ```bash
   git clone https://github.com/Horizon-55/Frontend-AI-chatbot.git
   cd Frontend-AI-chatbot
   ```
2. Встановити залежності:
   ```bash
   npm install
   ```

## Розробка

- Старт дев-сервера:
  ```bash
  npm run dev
  ```
  Відкрийте посилання з терміналу (типово `http://localhost:5173`). Vite автоматично перезбирає застосунок при змінах у `src/`.

- Лінтинг TypeScript:
  ```bash
  npm run lint
  ```

## Збірка

- Продакшн-збірка:
  ```bash
  npm run build
  ```
  Вихід потрапить до каталогу `dist/`.

- Перегляд локальної продакшн-збірки:
  ```bash
  npm run preview
  ```

## Інтеграція Puter AI

1. Скрипт SDK підключено у `index.html`:
   ```html
   <script src="https://js.puter.com/v2/" defer></script>
   ```
2. Перевірка готовності відбувається в `src/App.tsx` через `window.puter?.ai`. Коли SDK завантажився, інтерфейс змінює статус на “AI is ready”.
3. Перед першим викликом API потрібно авторизуватися:
   - Або виконати `window.puter.auth.signIn()` у консолі/кодові.
   - Або налаштувати токен Puter (див. офіційну документацію), зберігши його у змінній середовища та ініціалізувавши SDK.
4. Поточний виклик у `sendMessage` очікує метод `window.puter.ai.chat.completions.create`. Переконайтесь, що:
   - Обрано валідну модель (наприклад, `claude-sonnet-4` чи іншу, доступну на вашому тарифі).
   - Структура `messages` відповідає API Puter.
   - У відповіді дійсно є поле з текстом (за потреби адаптуйте парсер).

## Структура

- `src/main.tsx` — точка входу React, підключення стилів.
- `src/App.tsx` — основний компонент: стани чату, робота з Puter, рендер інтерфейсу.
- `src/index.css`, `src/App.css` — глобальні й компонентні стилі.
- `src/global.d.ts` — декларація необов’язкових типів для `window.puter`.

## Робочий процес

- Повідомлення користувача додаються через `addMessage`.
- `sendMessage` керує життєвим циклом: валідація, додавання повідомлення, виклик Puter, обробка відповіді.
- `isLoading` блокує інпут та показує індикатори очікування.
- `messagesEndRef` прокручує історію вниз після кожного оновлення.

## Відомі питання

- 401 Unauthorized: перевірити автентифікацію Puter.
- 400 Bad Request: переконатися, що викликається правильний метод SDK з усіма обов’язковими полями.
- “No reply received”: структура відповіді від Puter не відповідає парсеру. Увімкніть `console.log(response)` та підлаштуйте відображення.

## Подальші кроки

- Додати .env-конфіг для токенів (`VITE_PUTER_TOKEN`) та ініціалізувати SDK через змінні середовища.
- Розширити `ChatMessage` додатковими полями (наприклад, роль, часові мітки).
- Винести логіку роботи з Puter у окремий сервіс (`src/lib/puterClient.ts`) для кращого тестування.
